# 出題データ

出題データとジングル SE はリポジトリルートに置き、オンライン版と凍結 `poc/` で共有している。
`llm-poc` は問題データを使わない。

**出題データとジングル SE はリポジトリに含まれていない**（`.gitignore` で除外）。
各自でローカルに配置する。

ただしデータ形式のサンプルとして、`questions_example.csv` と対応する 1 問分の音声（`20260820/0-20260820.wav` / `.txt` / `.lab`）のみ追跡している。
`questions_example.csv` を `questions.csv` にコピーすれば、この 1 問で動作する。

```bash
cp quiz_data/questions_example.csv quiz_data/questions.csv
```

現状、オンライン版の各行には `.wav` / `.txt` / `.lab` の 3 点が必要である。
欠けているとサーバは起動するが、`/host` `/player` `/ws` は 503 で閉じる。

## 問題データ — `quiz_data/`

問題文と正解は `questions.csv` で管理し、VOICEPEAK の出力ファイルは**リネームせず**バッチ（日付）フォルダにそのまま置く。

```
quiz_data/
├── questions_example.csv   ← サンプル（追跡対象）
├── questions.csv           ← 実データ（各自で用意）
├── 20260820/          ← サンプルバッチ
│   └── 0-20260820.wav / .txt / .lab
└── 20260821/          ← バッチ = VOICEPEAK プロジェクト 1 つ
    ├── 00-20260821.wav / .txt / .lab
    ├── 01-20260821.wav / .txt / .lab
    ├── ...
    ├── 10-20260821.wav / .txt / .lab
    ├── 20260821.txt   ← 使用しない（VOICEPEAK の全体出力）
    ├── 20260821.lab   ← 使用しない（VOICEPEAK の全体出力）
    └── 20260821.vpp   ← 使用しない（VOICEPEAK プロジェクト）
```

`questions.csv` は 5 列。

```csv
batch,seq,text,answer,alt_answers
20260820,0,日本で一番高い山は富士山ですが、世界で一番高い山はどこ？,エベレスト,
20260821,0,大蛇を意味する名を持つプログラミング言語は何でしょう？,Python,パイソン|ニシキヘビ
```

2 行目は `alt_answers` の列の例である。
サンプルとして追跡しているのは 1 行目（`20260820`）だけ。

| 列 | 内容 |
| --- | --- |
| `batch` | バッチ名（`YYYYMMDD`）。`quiz_data/{batch}/` に対応 |
| `seq` | VOICEPEAK が出力した連番（0 起点）。`{seq}-{batch}.wav` などに対応。**整数で書く**（`0` でも `00` でも同じ） |
| `text` | 問題文。**改行を含めない**（1 問 1 ブロック） |
| `answer` | 正解 |
| `alt_answers` | 別解。`\|` 区切りで複数指定可。無ければ空 |

VOICEPEAK は連番を 0 起点でしか振れず接頭語も付けられないため、バッチフォルダと連番の組で一意性を与えている。

ファイル名が `{seq}-{batch}` となっているのは、VOICEPEAK が連番だけの出力を許さず接尾語が必須のため。
接尾語にはバッチ名（日付）をそのまま指定する。
フォルダ名と接尾語が一致するので、別の日のファイルを取り違えて置いた場合に参照先が見つからず検出できる。

### 音声なしで出題する

`.wav` / `.txt` / `.lab` を用意せず、`questions.csv` に行を足すだけでも出題できる。
読み上げ音声は鳴らず、問題文が 1 文字ずつ等速で表示される。

VOICEPEAK での音声生成を待たずに問題を足したいときに使う。

判定は行ごとに、実ファイルの有無で自動的に決まる。CSV に列は足さない。

| `.wav` / `.txt` / `.lab` | 扱い |
| --- | --- |
| 3 つとも揃っている | 音声あり問題（読み上げに同期して文字が出る） |
| 3 つとも無い | **音声なし問題**（等速の文字送り） |
| 一部だけある | **エラー**。起動ログに理由が出て、オンライン版の入口が 503 で閉じる |

「一部だけある」をエラーにしているのは、ファイルの置き忘れ・置き間違いを
検出するため。ここを音声なしへ倒すと、音声を用意したはずの問題が無音で
出題され、本番まで気づけない。

#### 別バッチに置くことを推奨する

音声なし問題は、音声ありとは**別のバッチ名**にするとよい。

```csv
batch,seq,text,answer,alt_answers
20260821,0,（音声あり問題）,答え,
csvonly,0,音声を用意していない問題です？,答え,
```

同じバッチに混ぜても動くが、連番の付け方によっては注意が要る。
ファイル名のゼロ埋め桁数はバッチ内の連番の最大値で決まるため
（次の[連番のゼロ埋め](#連番のゼロ埋め)を参照）、大きな `seq` の音声なし問題を
足すと想定桁数が変わる。実装側では複数の桁数を試して既存の問題を
見失わないようにしているが、バッチを分けておけば干渉そのものが起きない。

#### 文字送りの速度

既定は 1 文字あたり 120ms。`server` の環境変数で変更できる。

```bash
QUIZ_CHAR_INTERVAL_MS=300 uv run uvicorn app.main:app --port 8000
```

句読点でのウェイトは入れず、単純な等速で送る。
早押しされた時点で表示が止まるのは音声あり問題と同じで、
ジングル（`set` / `buzz` など）も従来どおり鳴る。

### 連番のゼロ埋め

VOICEPEAK は、**同じ接尾語で出力したファイル数**に応じて連番をゼロ埋めする。

| 1 バッチの出力数 | 連番 |
| --- | --- |
| 9 個以下 | `0`〜`8`（ゼロ埋めなし） |
| 10〜99 個 | `00`〜`99`（2 桁） |
| 100 個以上 | `000`〜（3 桁） |

境界は連番の値ではなく**出力数**で決まる。9 個なら 1 桁、10 個なら 2 桁になる。

桁数はバッチ内の `seq` の最大値から自動で判定するため、`questions.csv` には**整数で書けばよい**（`0` でも `00` でも同じ結果になる）。
表計算ソフトで開くとゼロ埋めは数値として桁落ちするので、CSV 側の表記に依存しない作りにしている。

### 同居してよいファイル

VOICEPEAK は連番ファイルとは別に、全体を連結した `{batch}.txt` / `{batch}.lab` も出力する。
また出力元のプロジェクトファイル `{batch}.vpp` を同じフォルダで管理すると分かりやすい。
いずれも本システムからは使用しないが、**置いたままで問題ない**（`questions.csv` 起点で参照するため、これらを読みに行くことはない）。

### 問題を追加する手順

**音声つきで追加する場合:**

1. `questions.csv` の `text` 列を表計算ソフトでまとめて選択し、VOICEPEAK に貼り付ける（改行がそのままブロック分割になる）
2. `quiz_data/{バッチ名}/` へ連番出力する。**接尾語にはバッチ名（日付）を指定する**（10 問なら `00-20260821.wav`〜`09-20260821.wav` のようになる）
3. 凍結 `poc/` を動かす場合は `npm run manifest -w poc` を実行する（オンライン版は CSV を直接読むので不要）

CSV の `text` と出力された `.txt` の中身が一致しない場合、どの行がズレているかを報告してビルドが止まる。
同日に作り直す場合は、同じフォルダへ先頭から再出力する。

**音声なしで追加する場合:**

`questions.csv` に行を足すだけでよい（[音声なしで出題する](#音声なしで出題する)を参照）。
ファイルの用意は要らない。後から音声を作る場合は、3 点セットを揃えて置けば
自動的に音声あり問題として扱われる。
